Все цифры на этой странице — **целевые бюджеты и расчётные оценки**. Замеряем их на фазе 0 и пилоте; если замер расходится с оценкой больше чем на 30%, обновляем страницу и связанные решения.

## Бюджеты агента

Эталонный ПК: 4 ядра, 8 ГБ памяти, SSD, Windows 11, один монитор 1920×1080, офисная нагрузка.

| ID | Метрика | Бюджет |
|---|---|---|
| NFR-01 | Средняя загрузка CPU службой и помощником вместе за рабочий день | ≤ 1% от одного ядра |
| NFR-02 | Пик CPU при снимке (захват, размытие, хэш, WebP) | ≤ 15% одного ядра, ≤ 250 мс |
| NFR-03 | Память: служба | ≤ 40 МБ рабочего набора |
| NFR-04 | Память: помощник в фоне | ≤ 60 МБ рабочего набора |
| NFR-05 | Память: окно сотрудника (только пока открыто) | ≤ 150 МБ |
| NFR-06 | Запись на диск | ≤ 50 МБ в час в среднем |
| NFR-07 | Сеть, среднее за рабочий час при политике по умолчанию | ≤ 3 МБ |
| NFR-08 | Сеть, пиковая скорость отправки | ограничивается политикой, по умолчанию 256 кбит/с |
| NFR-09 | Время запуска помощника после входа пользователя | ≤ 5 с |
| NFR-10 | Влияние на время входа в систему | не измеримо (служба стартует с отложенным автозапуском) |

Агент сам следит за бюджетами: если среднее за 10 минут превышено, он увеличивает интервал снимков и отправляет событие `budget_exceeded`. Job Object ограничивает помощника жёстко ([Агент](agent.html#zhiznennyi-tsikl-pomoshchnika)).

## Расчёт трафика и хранения

Допущения (оценка):

| Параметр | Значение |
|---|---|
| Снимков-кандидатов в час | 12 по интервалу + около 10 по смене окна = 22 |
| Отброшено дедупликацией | 50% |
| Средний кадр WebP после масштабирования | 120 КБ |
| Событий телеметрии в час | около 2000, около 150 байт каждое до сжатия |
| Рабочих часов в день | 8 |

Отсюда на один ПК:

- кадры: 22 × 0,5 × 120 КБ ≈ **1,3 МБ в час**, около 10,5 МБ в день;
- события: 2000 × 150 Б ≈ 0,3 МБ в час до сжатия, около 0,1 МБ после zstd.

| Парк | Кадры в день | Кадры за 90 дней (≈ 63 рабочих дня) | События в год в PostgreSQL (сжатие zstd) |
|---|---|---|---|
| 200 ПК | 2,1 ГБ | 130 ГБ | около 20 ГБ |
| 500 ПК | 5,3 ГБ | 330 ГБ | около 50 ГБ |
| 2000 ПК | 21 ГБ | 1,3 ТБ | около 200 ГБ |

К объёму S3 добавляем коэффициент репликации хранилища (×2 или ×3) и миниатюры (около 5% от кадров).

## Размеры серверов

| Парк | Схема | Ресурсы (оценка) |
|---|---|---|
| до 200 ПК | Одна ВМ, Docker Compose, PostgreSQL + файловое хранилище | 8 vCPU, 32 ГБ, 500 ГБ SSD |
| 200–1000 ПК | ВМ приложений (шлюз, API, воркеры) + ВМ данных (PostgreSQL) + SeaweedFS на 3 узлах | приложения 8 vCPU / 16 ГБ; данные 8 vCPU / 32 ГБ / 1 ТБ SSD; OCR 8 vCPU / 16 ГБ |
| 1000–5000 ПК | Схема из [Архитектуры](architecture.html#razvertyvanie-servera), Kubernetes или ВМ | 2× шлюз, 2× API, PostgreSQL с репликой, OCR-воркеры по нагрузке; выделенная аналитическая СУБД — только если события перестанут помещаться в PostgreSQL |

## Доступность и надёжность

| ID | Требование |
|---|---|
| NFR-11 | Доступность приёма данных — 99,5% в месяц; недоступность сервера до 7 суток не приводит к потере данных (очередь агента) |
| NFR-12 | Доступность консоли — 99% в рабочее время |
| NFR-13 | RPO для PostgreSQL — 15 минут, для S3 — 24 часа; RTO — 4 часа |
| NFR-14 | Потеря событий между агентом и сервером — 0 при штатной работе; дубликаты допустимы и устраняются |
| NFR-15 | Агент переживает аварийное выключение ПК без порчи очереди |

## Масштабирование

| ID | Требование |
|---|---|
| NFR-16 | Один экземпляр шлюза держит не меньше 2000 одновременных подключений агентов |
| NFR-17 | Приём масштабируется горизонтально добавлением экземпляров шлюза за балансировщиком |
| NFR-18 | OCR-конвейер масштабируется числом воркеров; задержка распознавания при штатной нагрузке ≤ 10 минут |
| NFR-19 | Отчёт «время в приложениях» по подразделению в 100 человек за месяц строится ≤ 3 с |
| NFR-20 | Поиск по тексту за 30 дней по организации в 2000 ПК — ≤ 5 с |

## Совместимость

| ID | Требование |
|---|---|
| NFR-21 | Windows 10 22H2 и Windows 11 (23H2 и новее), x64; Windows Server 2019/2022 с ролью RDS |
| NFR-22 | Несколько мониторов с разным масштабом, гибридная графика ноутбуков |
| NFR-23 | Корректная работа под антивирусами Kaspersky Endpoint Security, Dr.Web, Microsoft Defender — при добавлении исключений из нашей памятки или без них |
| NFR-24 | Сервер — любой Linux с Docker или Kubernetes; поддержка отечественных ОС (Astra Linux, РЕД ОС) для серверной части проверяется на фазе 3 |

## Сопровождаемость и локализация

- Интерфейс консоли и окна сотрудника — на русском, тексты вынесены в файлы локализации.
- Журналы сервиса — структурированный JSON, метрики в формате Prometheus, трассировки OpenTelemetry.
- Агент отправляет собственные метрики здоровья (CPU, память, размер очереди, метод захвата, ошибки) — они видны в разделе «Агенты».
