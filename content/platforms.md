Агент 1.0 работает на Windows. План кроссплатформенной работы расширяет поддержку на Linux и позже на macOS. Главное — быстрый и качественный старт у первых заказчиков, простая установка и простое отслеживание развёртывания.

!!! note "Это план, а не обещание сроков"
    Ниже — порядок работ и оценки сложности, а не календарные даты. Цифры объёмов и нагрузки берутся из документации и помечены как оценки; их подтверждают на пилоте.

## Коротко

- **Первая версия (MVP) — Windows и Linux (X11).** Linux: Astra Linux SE, РЕД ОС, ALT.
- **Отложено на потом:** Linux Wayland, arm64, Windows Server 2025 и **macOS** (решение по юрлицу для Apple не принято, поэтому macOS идёт последним этапом и ничего не блокирует).
- **Одно ядро на Go, тонкие адаптеры под каждую ОС.** Очередь, отправка, политика, размытие, бюджет нагрузки и обновления — в общем ядре; под ОС пишутся только «датчики».
- **Нет видимого значка — нет сбора.** Если окна мессенджеров нельзя размыть на этой системе, снимков нет. Агент сообщает, что он реально умеет на конкретном ПК.

## Этапы выпуска

| № | Этап | Что входит | Критерий готовности |
|---|---|---|---|
| 0 | Основа качества и ядро | вынести ядро из Windows-агента, матрица возможностей, правила отказа, CI на настоящих ВМ и smoke для Windows и Linux, процессы безопасной разработки | Windows-агент работает на новом ядре без регрессий и в пределах бюджета |
| 1 | Windows MVP | установщик сервера, токены и готовые команды, MSI с предпроверкой, самопроверка `doctor`, экран «Развёртывание» и оповещения, подпись кода | чистая установка и раскатка на тестовую группу по инструкции без участия разработчиков |
| 2 | Linux X11 MVP | служба и помощник X11, трей, окно сотрудника, deb/rpm, репозиторий на сервере, Ansible и Salt, подпись ELF; Ready for Astra параллельно | вся MVP-матрица зелёная; пакеты ставятся при включённых ЗПС и МКЦ |
| 3 | Пилот | смешанный парк Windows + Linux у первого заказчика | критерии пилота выполнены, цифры из документации подтверждены или исправлены |
| 4 | Сертификация ФСТЭК (если нужна заказчикам) | запрос в лабораторию, выбор уровня доверия, испытания замороженной версии | решение лаборатории |
| 5 | Linux Wayland | порталы GNOME/KDE, матрица поддержки по оболочкам | неподдержанное честно выключено |
| 6 | arm64 и новые серверные Windows | Windows on ARM, Linux arm64, Windows Server 2025 | e2e на arm64 |
| 7 | macOS (отложена) | прослойка Swift, LaunchDaemon и LaunchAgent, pkg, подпись и нотаризация, MDM-профили | начинать только после решения по Apple Developer Program |

Этапы 1 и 2 после этапа 0 можно вести параллельно; пилот начинается, когда готовы оба. Сертификация не держит пилот.

## Обновления кольцами

Новая версия агента раскатывается постепенно и отдельно для каждой ОС: `canary` (несколько ПК ИТ) → `early` (небольшая доля парка) → `broad` (все). Если в кольце растут ошибки или сборка не присылает сигнал «здоров» за отведённое время, раскатка этой ОС останавливается и откатывается. На Linux кольца — это каналы репозитория.

## Качество

Качество закладывается с первого дня, а не в конце:

- **Smoke на настоящих виртуальных машинах на каждую сборку** для каждой ОС из MVP-матрицы: установка пакетом → регистрация по токену → пульс → один снимок и одно событие дошли до сервера → `doctor` без ошибок → удаление без следов на ПК.
- **Контрактные тесты адаптеров** на каждую ОС: «открыли окно → событие с его заголовком», «окно мессенджера на экране → область на кадре размыта», «вставили USB → событие с VID/PID».
- **Ночные полные e2e**, включая терминальные серверы, USB и блокировку экрана.
- **Нагрузка и долгий прогон** — 8 часов рабочего дня против бюджета из [«Требования и стек»](spec.html) (≤ 1% ядра, ≤ 40 МБ памяти службы, ≤ 3 МБ сети в час); сервер под симуляцией 200 и 1000 агентов.
- **Проверка принципов** на каждой ОС: нет хуков клавиатуры, нет чтения буфера обмена, значок нельзя скрыть политикой, без значка сбор с привязкой к человеку не идёт, сервер не может выполнить команду на ПК.
- **Безопасность:** статический анализ, проверка зависимостей, фаззинг разбора политик и протокола, поиск секретов. Отчёты сохраняются — они же нужны для сертификации.

Красная строка любой ОС в отчёте сборки блокирует релиз.

## Сертификация

Ориентир: сертифицироваться, если это нужно заказчикам, но не тормозить старт. Пилот идёт на несертифицированной версии, а всё, что потом дорого переделывать, закладывается сразу.

- **Ready for Astra** — программа технологического партнёрства «Группы Астра»: установка, работа и удаление ПО на Astra SE при включённых ЗПС и МКЦ. Вступление и ключи подписи — в начале этапа Linux; подача на испытания — в конце, параллельно пилоту.
- **Реестр российского ПО** — для закупок части заказчиков может требоваться подтверждённая совместимость с отечественными ОС (Ready for Astra плюс программы РЕД ОС или ALT). **[Проверить условия для класса продукта.]**
- **ФСТЭК** — требования по уровням доверия (приказ № 76 от 02.06.2020). Процессы безопасной разработки и нужные архитектурные решения закладываются с этапа 0; заявку подают на замороженную версию после пилота, если она нужна заказчикам.

## Что нужно решить

1. Для каких систем у первых заказчиков нужна «Ясность» (ИСПДн и её уровень, ГИС, значимые объекты КИИ или обычная сеть) — от этого зависит, нужна ли сертификация ФСТЭК к пилоту и на какой уровень доверия.
2. Конкретные версии ОС у первых заказчиков и есть ли терминальные серверы — это сужает MVP-матрицу.
3. На какое юридическое лицо оформлять подпись кода Windows, партнёрство Ready for Astra и, при необходимости, заявку в лабораторию ФСТЭК.
