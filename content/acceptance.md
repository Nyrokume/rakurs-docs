## Уровни тестирования

| Уровень | Что проверяем | Инструменты | Когда |
|---|---|---|---|
| Модульные | Слияние политик, дедупликация, маскирование, разбор протокола | `cargo test`, `go test`, фаззинг | Каждый коммит |
| Интеграционные | Агент ↔ шлюз, шлюз ↔ ClickHouse/S3, воркеры | Тестовые контейнеры, эмулятор агента | Каждый пулреквест |
| Сквозные | Установка MSI → регистрация → снимки → консоль | Стенд из ВМ, сценарии на Playwright для консоли | Ночная сборка |
| Совместимость | Матрица ОС, мониторов, антивирусов | Стенд ВМ + несколько физических ПК | Перед каждым релизом |
| Нагрузочные | 2000 эмулированных агентов, сутки работы | Эмулятор агентов на Go, k6 для API | Перед релизом, после изменений протокола |
| Долговременные | Агент 14 суток без перезагрузки: утечки памяти, рост очереди | Счётчики производительности, ETW | Перед релизом |
| Безопасность | Пентест, фаззинг, проверка зависимостей | Внешняя команда, `cargo fuzz`, `govulncheck` | Фаза 4 и крупные изменения |
| Юридическая проверка | Соответствие собираемых данных приказу | Чек-лист с юристом | Перед пилотом и тиражом |

## Матрица стендов

| Конфигурация | Зачем |
|---|---|
| Windows 10 22H2, один монитор | Базовая |
| Windows 11 24H2, два монитора 100% и 150% | DPI, несколько мониторов |
| Ноутбук с гибридной графикой | DXGI на правильном адаптере |
| Windows Server 2022 RDS, 10 сессий | Терминальный режим |
| ВМ без GPU (Hyper-V, VMware) | Откат на WGC/GDI |
| Kaspersky Endpoint Security, Dr.Web, Defender | Совместимость с антивирусами |
| Медленный канал 256 кбит/с, потери 5% | Очередь, обратное давление |
| Без сети 7 суток | Автономность |

## Критерии приёмки

| Требование | Критерий | Метод |
|---|---|---|
| FR-01 | За рабочий час при политике по умолчанию сделано 12 интервальных снимков ±1 и снимки по каждой смене окна с учётом `minGap` | Сквозной тест со сценарием переключений |
| FR-02 | Окно из `skip` не попадает ни в один кадр; окно из `blur` нечитаемо (OCR по области возвращает пустой результат) | Автотест с эталонными окнами + ручная проверка 50 кадров |
| FR-03 | На статичном экране за час уходит не больше 2 кадров; на активной работе отбрасывается от 20% кадров | Сквозной тест, замер на пилоте |
| FR-04 | Каждый сборщик выдаёт события с полями из [модели данных](data-model.html); старт процесса фиксируется ≤ 2 с | Интеграционные тесты |
| FR-05 | После 7 суток без сети при квоте 2 ГБ события не потеряны, кадры вытеснены по приоритету | Тест автономности |
| FR-06 | Новая политика применяется ≤ 15 мин без перезапуска; политика с неверной подписью отклоняется | Интеграционный тест |
| FR-07 | Обновление раскатывается по кольцам; при сбое старта новой версии — откат ≤ 3 мин | Сквозной тест с намеренно сломанной сборкой |
| FR-08 | Значок в трее виден всегда, окно открывается ≤ 2 с, перечень данных совпадает с политикой | Ручная проверка + снимок экрана |
| FR-09 | Без отметки об ознакомлении нет ни одного кадра и события с `person_id` | Запрос к ClickHouse после суток работы |
| FR-10 | Перезапуск шлюза под нагрузкой не приводит к потере событий | Нагрузочный тест с убийством подов |
| FR-11 | Текст на эталонных снимках распознаётся с точностью по символам ≥ 95% для интерфейсного шрифта 100% масштаба | Набор из 200 эталонных кадров |
| FR-12 | Все экраны консоли из [списка](console.html#ekrany) работают на данных пилота | Приёмка заказчиком по сценариям |
| FR-13 | Политика с ошибкой схемы не публикуется; сравнение версий показывает разницу | Сценарии Playwright |
| FR-14 | Оповещение о запрещённом ПО приходит ≤ 60 с после запуска | Сквозной тест |
| FR-15 | Каждый просмотр кадра есть в аудите с причиной, в том числе просмотры руководителем; при `viewNotice: onView` сотрудник видит уведомление в окне агента; удаление записи из аудита невозможно ролью приложения; подмена записи обнаруживается проверкой цепочки | Тест безопасности |
| FR-16 | Данные старше срока отсутствуют в ClickHouse и S3 через ≤ 24 ч после истечения | Тест с укороченными сроками |
| FR-17 | Отключённая в AD учётная запись помечается уволенной ≤ 30 мин; события доходят до SIEM | Интеграционный тест |
| FR-18 | Выгрузка данных сотрудника формируется ≤ 1 ч и содержит все классы данных | Сквозной тест |
| NFR-01…10 | Бюджеты из [Производительности](performance.html) выдержаны на эталонном ПК за 8-часовой сценарий | Долговременный тест, счётчики производительности |
| RBAC | Руководитель открывает ленту дня и кадры сотрудников своего подразделения; запрос к сотруднику другого подразделения отклоняется сервером (403) и пишется в аудит | Интеграционный тест API, сценарии Playwright |
| NFR-16…20 | Пороговые значения выдержаны на 2000 эмулированных агентах | Нагрузочный тест |

## Порядок испытаний

1. **Предварительные испытания** на стенде: все критерии выше, протокол с результатами.
2. **Пилот** на 30–50 ПК в течение 4–6 недель: метрики нагрузки и объёма, опрос участников, журнал замечаний.
3. **Приёмочные испытания** по программе и методике испытаний (ПМИ), согласованной с заказчиком; приёмка оформляется актом.
4. **Опытная эксплуатация** на первом кольце тиража (25% парка) — 2 недели.

Замечания классифицируются: блокирующие (приёмка невозможна), значимые (исправить до тиража), незначительные (в план работ).
