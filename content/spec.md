«Ясность» ставится в контуре организации. Ниже — технологии, из которых она собрана, и требования к серверу и рабочим ПК. Цифры объёмов — расчётные оценки для планирования, их уточняют на пилоте.

## Стек

| Часть | Среда и технологии |
|---|---|
| Агент | Windows 10 (22H2)/11 x64, Windows Server 2019/2022 с RDS; язык Go |
| Сервер | Linux в контуре организации, контейнеры; язык Go, один бинарник `yasnost-server`, запускается в ролях (`--role`) |
| Хранилище | PostgreSQL (метаданные, события, текст OCR, аудит) + S3-совместимое хранилище снимков |
| Распознавание текста | Tesseract (rus+eng) на сервере |
| Консоль | Веб-приложение (React + TypeScript), раздаётся сервером |
| Транспорт | gRPC поверх mTLS (агент→сервер), REST/JSON (консоль→сервер) |
| Интеграции | Active Directory, SIEM (syslog/CEF) |

Один язык на агенте и сервере (Go) и один основной хранитель данных (PostgreSQL) — сознательное решение: меньше движущихся частей, проще поддерживать и разворачивать. Сервер — это один бинарник (модульный монолит): для небольших установок он работает одним процессом, а при росте парка те же роли (`gateway`, `api`, `worker-ocr`) запускаются отдельными экземплярами. Подробнее — на странице [«Архитектура системы»](architecture.html).

## Требования к рабочему ПК

- Windows 10 22H2 или Windows 11, x64; Windows Server 2019/2022 с ролью RDS.
- 500 МБ свободного места (до 2 ГБ берутся под очередь по возможности).
- Исходящий доступ к серверу по TCP (один порт, по умолчанию 8443).
- WebView2 Runtime для окна сотрудника (в Windows 11 встроен). Без него трей и сбор работают, не открывается только окно сотрудника.
- Нагрузка на ПК по бюджету: в среднем ≤ 1% одного ядра за день, ≤ 40 МБ памяти у службы, ≤ 3 МБ сети в час при политике по умолчанию.

## Размеры сервера

| Парк | Схема | Ресурсы (оценка) |
|---|---|---|
| до 200 ПК | одна ВМ, Docker Compose, PostgreSQL + файловое хранилище | 8 vCPU, 32 ГБ, 500 ГБ SSD |
| 200–1000 ПК | ВМ приложений + ВМ данных (PostgreSQL) + S3 на 3 узлах | приложения 8 vCPU / 16 ГБ; данные 8 vCPU / 32 ГБ / 1 ТБ SSD |
| 1000–5000 ПК | шлюз и API в нескольких экземплярах, PostgreSQL с репликой, OCR-воркеры по нагрузке | по расчёту под парк |

## Сколько накопится данных

Оценка при политике по умолчанию (снимок раз в 5 минут, половина кадров отбрасывается, 8 рабочих часов):

| Парк | Снимки в день | Снимки за 90 дней | События за год в PostgreSQL |
|---|---|---|---|
| 200 ПК | 2,1 ГБ | 130 ГБ | около 20 ГБ |
| 500 ПК | 5,3 ГБ | 330 ГБ | около 50 ГБ |
| 2000 ПК | 21 ГБ | 1,3 ТБ | около 200 ГБ |

К объёму снимков добавляется коэффициент репликации хранилища (×2–×3) и миниатюры (около 5%).

## Доступность

- Приём данных — цель 99,5% в месяц; недоступность сервера до 7 суток не теряет данные (очередь агента).
- Консоль — цель 99% в рабочее время.
- Резервное копирование PostgreSQL — непрерывный архив WAL плюс суточная полная копия; цель восстановления — 4 часа.
