Короткий ответ: **агент пишем на Rust, сервер на Go, консоль — веб-приложение на TypeScript.** Ниже разбор, почему именно так и когда стоит выбрать один язык на всё. Итоговое решение оформлено в [ADR-001](adr.html#adr-001).

## Чем агент отличается от сервера

Агент и сервер — разные по природе программы, и требования к языку у них разные.

| | Агент на ПК | Сервер |
|---|---|---|
| Сколько экземпляров | Сотни и тысячи, на чужих ПК | Единицы, на наших серверах |
| Главный ресурс | Память и CPU пользователя | Время разработчиков |
| Работа с ОС | Глубокая: COM, WinRT, DXGI, ETW, токены сессий | Обычная: сеть, диски, базы |
| Цена ошибки | Падение или утечка памяти на всём парке, жалобы пользователей | Перезапуск пода |
| Обновление | Раскатка кольцами, дни | Минуты |

Отсюда логика: для агента важны предсказуемая память, отсутствие сборщика мусора, близость к WinAPI и безопасность при работе с указателями из C-интерфейсов. Для сервера — скорость разработки, простота кода и найм.

## Сравнение по частям системы

### Служба Windows и сессии

Служба Windows живёт в **сессии 0** и с Windows Vista изолирована от рабочего стола пользователя: экран из неё не снять, окна не перечислить. Поэтому агент — это два процесса: служба (SYSTEM, сессия 0) и помощник (от имени пользователя, в его сессии). Служба запускает помощника через `WTSQueryUserToken` + `CreateProcessAsUserW` при входе пользователя и следит, чтобы он был жив. Подробно в разделе [Агент](agent.html).

| | Rust | Go |
|---|---|---|
| Служба | крейт `windows-service`: регистрация, обработчик команд SCM | `golang.org/x/sys/windows/svc` — зрелый, используется широко |
| WinAPI | крейт `windows` от Microsoft, генерируется из метаданных Windows SDK; покрывает Win32, COM и WinRT | `golang.org/x/sys/windows` покрывает Win32; COM и WinRT — через сторонние обёртки или вручную через таблицы виртуальных методов |
| Потоки и COM | Явное управление потоками, COM-апартаменты без сюрпризов | Горутины мигрируют между потоками ОС; для COM нужен `runtime.LockOSThread`, ошибиться легко |
| Итог | **Сильнее** | Достаточно для службы, слабее для COM/WinRT |

### Захват экрана

Три API, у каждого своя ниша. Подробности и стратегия отката — в [Захват и OCR](capture.html).

| API | Что умеет | Rust | Go |
|---|---|---|---|
| DXGI Desktop Duplication (Windows 8+) | Кадр всего монитора из GPU, список изменённых областей, курсор отдельно | `windows` крейт напрямую; готовые крейты `windows-capture`, `xcap` | Только вручную через COM-вызовы |
| Windows.Graphics.Capture (Windows 10 1803+) | Захват монитора или конкретного окна, работает с DPI и HDR | `windows` крейт (WinRT-проекция), `windows-capture` | Нет зрелой обёртки WinRT |
| GDI BitBlt | Самый старый, работает везде, медленный, не видит часть аппаратно ускоренного контента | Через `windows` крейт | `kbinani/screenshot` и аналоги |

Для Go реалистичный путь — GDI через готовую библиотеку, а DXGI и WGC писать самим поверх COM. Для Rust все три метода доступны из официального крейта.

### Процессы, окна, реестр, WMI

| Задача | Rust | Go |
|---|---|---|
| Процессы | `sysinfo`; напрямую ToolHelp32 или `NtQuerySystemInformation` через `windows` | `gopsutil`; ToolHelp32 через `x/sys/windows` |
| Активное окно, заголовок, PID | `GetForegroundWindow`, `GetWindowTextW`, `GetWindowThreadProcessId` | То же через syscall |
| События смены окна | `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` с циклом сообщений | То же, но цикл сообщений нужно держать на закреплённом потоке |
| Простой | `GetLastInputInfo` | То же |
| Реестр | крейт `winreg` или `windows` | `golang.org/x/sys/windows/registry` — стандартный и удобный |
| WMI | крейт `wmi` с десериализацией через serde | `yusufpapurcu/wmi` (форк StackExchange/wmi) |

Здесь паритет: обе экосистемы закрывают задачу. У Go реестр даже удобнее из коробки.

### ETW

ETW (Event Tracing for Windows) даёт события ядра и системы почти без накладных расходов: старт и завершение процессов, сетевые соединения, загрузку образов. Это лучший способ не опрашивать список процессов раз в секунду.

| | Rust | Go |
|---|---|---|
| Потребитель ETW в реальном времени | `ferrisetw`: сессии, провайдеры, разбор схем TDH | Сторонние библиотеки (например, `bi-zone/etw`); выбор меньше, актуальность нужно проверять |
| Нагрузка | Колбэки без сборщика мусора, удобно для потока событий | Работает, но поток событий создаёт давление на GC |

### OCR

| Движок | Где запускать | Rust | Go |
|---|---|---|---|
| Windows.Media.Ocr | На агенте, бесплатно, встроен в Windows 10+; русский язык при установленном языковом пакете | Через WinRT-проекцию `windows` крейта | Практически недоступен без своей обёртки WinRT |
| Tesseract 5 | На сервере или агенте | Привязки через FFI (`leptess`, `tesseract-rs`) | `gosseract` через cgo |
| PaddleOCR (PP-OCR) через ONNX Runtime | На сервере, лучшая точность на снимках, есть GPU | Крейт `ort` | `onnxruntime_go` через cgo |

Решение для Ракурса: **OCR на сервере** (PaddleOCR через ONNX Runtime, запасной Tesseract), чтобы не грузить ПК пользователя. Windows.Media.Ocr оставляем как опцию для офлайн-режима и слабых каналов. Сервер на Go вызывает OCR-воркер как отдельный сервис, так что язык сервера здесь не важен.

### Кодирование и дедупликация кадров

| Задача | Rust | Go |
|---|---|---|
| WebP-кодирование | `webp` (libwebp), `image` | В стандартной библиотеке только декодер; для кодирования нужен cgo (libwebp) |
| AVIF | `ravif` (чистый Rust на rav1e), медленный, но без C | Только через cgo (libavif) |
| Перцептивный хэш | `image_hasher` (pHash, dHash, blockhash) | `goimagehash` |
| SIMD-масштабирование | `fast_image_resize` | Ограниченно |

Кодирование происходит на агенте, тысячи раз в день на каждом ПК. Отсутствие кодировщика WebP без cgo у Go — ощутимый минус: cgo усложняет сборку, кросс-компиляцию и профилирование.

### Транспорт

Паритет. `tonic` + `rustls` у Rust и `grpc-go` у Go — обе реализации зрелые, обе поддерживают mTLS. QUIC: `quinn` (Rust) и `quic-go` (Go). Для первой версии берём gRPC поверх HTTP/2 с mTLS: он проходит через корпоративные прокси и балансировщики, а QUIC (UDP) часто режется на периметре. См. [Протокол](protocol.html).

### GUI

На ПК пользователя GUI нужен для двух вещей: значок в трее и окно «Что обо мне собирается». Админ-консоль — веб, ей GUI-фреймворк не нужен.

| Фреймворк | Язык | Рендер | Плюсы | Минусы |
|---|---|---|---|---|
| **Tauri 2** | Rust | Системный WebView (WebView2 на Windows) | Интерфейс на HTML/CSS, общий с веб-консолью; трей, мультиокна, автообновление, подпись | Зависит от WebView2; память растёт, пока окно открыто |
| **Slint** | Rust (также C++, JS) | Собственный, GPU или софт | Маленький, быстрый, декларативный язык разметки, нет браузера | Свои компоненты, отдельная лицензия (GPLv3, бесплатная для десктопа или коммерческая) |
| **egui** | Rust | Immediate mode | Очень быстро делать служебные окна | Выглядит как инструмент разработчика, слабее доступность |
| **iced** | Rust | Собственный (wgpu) | Архитектура в стиле Elm, активно развивается | Меньше готовых компонентов |
| **Wails v3** | Go | Системный WebView | Стабильная версия с 26.10.2026: трей, мультиокна, службы; веб-интерфейс | Молодая стабильная ветка, API v3 несовместим с v2 |
| **Fyne** | Go | Собственный (OpenGL) | Единый вид везде, простой API | cgo, свой визуальный язык, крупные бинарники |
| **Gio** | Go | Immediate mode | Чистый Go, быстрый | Мало готовых виджетов, крутая кривая |

Выбор для агента — **Tauri 2**: окно открывается редко, процесс окна живёт только пока оно открыто, а интерфейс собирается из тех же компонентов, что и консоль. Если групповая политика запрещает WebView2, запасной вариант — Slint для того же окна. Трей держим в самом помощнике через крейт `tray-icon`, без WebView: это экономит память в фоне.

### Linux и macOS

| Платформа | Захват | Особенности |
|---|---|---|
| Linux, X11 | XShm / XGetImage, `xcap` (Rust) | Работает без согласия пользователя; Astra Linux (Fly) — проверить версию графического стека на целевых машинах |
| Linux, Wayland | Только через xdg-desktop-portal (ScreenCast) и PipeWire | Композитор спрашивает разрешение у пользователя; молчаливый захват по дизайну невозможен |
| macOS | ScreenCaptureKit | Нужно разрешение «Запись экрана» в настройках приватности; через MDM его нельзя выдать молча, только разрешить пользователю согласиться |

Rust здесь удобнее: `xcap` и `sysinfo` кроссплатформенные, а логика агента остаётся общей. Linux — вторая очередь, macOS вне первой версии ([Дорожная карта](roadmap.html)).

### Сервер, команда, скорость разработки

| | Rust | Go |
|---|---|---|
| CRUD API, консоль, интеграции | `axum`, `sqlx` — хорошо, но медленнее писать | `net/http`, `chi`, `pgx`, `clickhouse-go` — быстро и просто |
| Время компиляции | Минуты на большом проекте | Секунды |
| Найм в России | Rust-разработчиков меньше, они дороже | Go — один из основных языков бэкенда |
| Порог входа | Высокий: владение, время жизни, async | Низкий |
| Память и предсказуемость | Без GC, минимальный фон | GC, выше базовое потребление, паузы малы |

## Сводка сравнения

Оценка по пятибалльной шкале для **агента** и **сервера** отдельно. Это экспертная оценка, а не бенчмарк.

| Критерий | Rust · агент | Go · агент | Rust · сервер | Go · сервер |
|---|---|---|---|---|
| Доступ к WinAPI, COM, WinRT | 5 | 3 | — | — |
| Захват экрана (DXGI, WGC) | 5 | 2 | — | — |
| ETW | 4 | 3 | — | — |
| Кодирование WebP/AVIF без cgo | 5 | 2 | — | — |
| Память и фоновая нагрузка | 5 | 4 | 4 | 4 |
| Скорость разработки | 3 | 4 | 3 | 5 |
| Найм и порог входа | 2 | 4 | 2 | 5 |
| gRPC, базы, S3 | 4 | 5 | 4 | 5 |

## Рекомендация

**Rust для агента.** На ПК пользователя всё упирается в WinAPI, COM и WinRT: DXGI, Windows.Graphics.Capture, Windows.Media.Ocr, ETW. Официальный крейт `windows` от Microsoft даёт к ним прямой доступ, нет сборщика мусора, кодирование WebP и AVIF не требует cgo. Агент небольшой по объёму кода, и высокий порог входа Rust здесь окупается.

**Go для сервера.** Сервер — это приём потоков, базы, очереди, API консоли и интеграции. Go пишется быстрее, людей найти проще, `grpc-go`, `pgx`, `clickhouse-go` и S3-клиенты зрелые. Контракт между ними — `.proto`-файлы, из которых генерируются типы для обоих языков.

### Когда выбрать один язык

- **Всё на Go** (агент + Wails v3 для окна), если в команде нет и не будет Rust-разработчиков. Цена: DXGI и WGC придётся писать через COM вручную, WebP — через cgo, OCR на агенте практически недоступен. Рабочий вариант, если ограничиться GDI-захватом и сделать OCR только на сервере.
- **Всё на Rust** (`axum` на сервере), если команда маленькая и уже сильная в Rust. Цена: медленнее растёт консольный API и интеграции.
