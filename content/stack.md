Решение принято и дальше по всей документации идёт без «или»: **один язык — Go**, для агента и для сервера; консоль — **React + TypeScript**; данные — **PostgreSQL** и **S3-совместимое хранилище снимков**. Прежний план с Rust-агентом и ClickHouse оставлен в истории решений — [ADR-001](adr.html#adr-001) и [ADR-004](adr.html#adr-004) помечены как заменённые. Новые решения — [ADR-010](adr.html#adr-010) и [ADR-011](adr.html#adr-011).

## Стек одним взглядом

| Часть | Технология | Зачем |
|---|---|---|
| Агент (служба + помощник) | Go, `golang.org/x/sys/windows` | Один язык на всё; прямой доступ к Win32, службе, реестру |
| Захват экрана | DXGI Desktop Duplication | Быстрый захват без нагрузки на ПК; библиотека выбирается на фазе 0 |
| Трей и окно сотрудника | Go-трей + локальная веб-страница | Прозрачность без тяжёлого GUI-движка |
| Сервер | Go, один модульный монолит | Приём, OCR, API, раздача консоли — один бинарник |
| OCR | Tesseract (`rus+eng`) в воркере сервера | Распознавание на сервере, не на ПК пользователя |
| Консоль | React + TypeScript + Vite + shadcn/ui | Статика, которую раздаёт тот же Go-сервер |
| Данные | PostgreSQL + S3-хранилище (SeaweedFS) | Метаданные, события, текст OCR, аудит, очередь — в PostgreSQL; кадры — в S3 |
| Транспорт | gRPC/mTLS агент→сервер, REST/JSON консоль→сервер | Поток и кадры по gRPC, консоль по привычному REST |

## Почему один язык

Агент и сервер — разные по нагрузке программы, но держать ради этого два языка дорого: двойной найм, два набора CI и мост cgo/FFI на стыке. Go закрывает обе задачи:

- **На ПК** `golang.org/x/sys/windows` даёт службу Windows (`.../svc`), Win32, реестр (`.../registry`) и токены сессий. Захват экрана через DXGI Desktop Duplication подключается готовой библиотекой или тонкой cgo-обёрткой. ETW — по необходимости.
- **На сервере** Go — это быстрый приём потоков, работа с PostgreSQL (`pgx`), S3-клиент, gRPC (`grpc-go`) и REST для консоли в одном бинарнике.
- **Общий код.** Модели данных, валидация политик и типы из `.proto` переиспользуются между частями сервера без перевода на второй язык.

## Чем жертвуем

- **Память агента требует дисциплины.** У Go есть сборщик мусора и рантайм. На чужих ПК это значит: пулы буферов под кадры, явное освобождение нативных ресурсов захвата и OCR, профилирование под нагрузкой и предел памяти процесса. Это дешевле, чем держать в команде Rust.
- **Нативный захват — через cgo или библиотеку.** DXGI и кодирование кадров завязаны на C-API. Выбор конкретной библиотеки и способ обёртки фиксируем на фазе 0 и проверяем на стабильность и лицензию.
- **OCR только на сервере.** На агенте распознавания нет — для филиалов со слабым каналом это осознанное ограничение, а не фоновая опция.

## Когда вернёмся к вопросу

- **ClickHouse** — только если флот превысит несколько тысяч ПК и PostgreSQL перестанет держать аналитику по событиям. До этого порога — одна база (см. [Дорожную карту](roadmap.html)).
- **Отдельный брокер очередей** — только если поток кадров упрётся в очередь задач на PostgreSQL. На старте очередь живёт в самой базе ([ADR-009](adr.html#adr-009)).
- **Rust для «горячего» участка агента** — теоретически возможен точечно, но лишь после замеров, доказывающих, что Go не вытягивает. По умолчанию — нет.

Как это собирается в работающую систему и в каком порядке разрабатывается — на странице [Как мы строим «Ясность»](build.html).
