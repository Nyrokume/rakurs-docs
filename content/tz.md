## Что описывает ТЗ

ТЗ описывает, **что** должна делать система «Ракурс» и **как мы проверим**, что она это делает. Как именно реализовать — решают разработчики в рамках [архитектурных решений](adr.html). Требования пронумерованы: `FR` — функциональные, `NFR` — нефункциональные, `SEC` — безопасность, `LEG` — правовые. На номера ссылаются тест-план и критерии приёмки.

## Система и её назначение

**Ракурс** — система прозрачного мониторинга активности на рабочих компьютерах организации. Назначение:

- учёт фактически отработанного за компьютером времени (ст. 91 ТК РФ);
- анализ использования приложений и загрузки подразделений;
- инвентаризация программного и аппаратного обеспечения;
- сбор данных для расследования инцидентов информационной безопасности.

Система **не предназначена** для скрытого наблюдения, перехвата переписки и ввода, оценки сотрудников одним числом «продуктивности».

## Что входит в версию 1.0

| Входит | Не входит в версию 1.0 |
|---|---|
| Агент для Windows 10 (22H2) и Windows 11, x64; Windows Server 2019/2022 с RDS | macOS, мобильные устройства |
| Сервер на Linux (контейнеры) в контуре организации | Облачная SaaS-версия |
| Веб-консоль для администраторов, руководителей, ИБ, аудитора | Мобильное приложение консоли |
| Окно сотрудника на ПК | Онлайн-трансляция экрана |
| OCR и поиск по тексту на снимках | Блокировка приложений и сайтов |
| Интеграция с Active Directory, SIEM | Интеграция с DLP-шлюзами (после 1.0) |
| — | Агент для Linux (Astra, РЕД ОС) — версия 1.1 |

## Участники и роли

| Роль | Что делает в системе |
|---|---|
| Владелец системы | Утверждает политики и состав собираемых данных, отвечает перед руководством |
| Администратор системы | Развёртывание, агенты, интеграции; **без доступа к снимкам** по умолчанию |
| Офицер ИБ | Расследования, правила, доступ к снимкам с указанием причины |
| Руководитель подразделения | Агрегированные отчёты по своему подразделению; снимки — только если разрешено политикой |
| Аудитор | Только чтение журнала аудита, без доступа к данным сотрудников |
| Сотрудник | Видит свои данные и список того, что собирается |

Подробная матрица прав — в [Безопасности](security.html#rbac).

## Как работать с этим ТЗ

- Изменения в ТЗ — через пулреквест в этот репозиторий; страница меняется вместе с номером требования.
- Требование, которое нельзя проверить, не принимается: у каждого `FR` и `NFR` есть строка в [тест-плане](acceptance.html).
- Спорные места собраны в [Открытых вопросах](questions.html); пока вопрос открыт, связанное требование считается черновиком.
