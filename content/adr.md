Формат записи: статус, контекст, решение, альтернативы, последствия. Статус «Принято» означает «принято для старта разработки»; после фазы 0 часть решений подтверждаем замерами.

## ADR-001. Rust для агента, Go для сервера {#adr-001}

**Статус:** принято, подтвердить после фазы 0.

**Контекст.** Агент работает на сотнях и тысячах ПК от имени SYSTEM и пользователя, активно использует COM и WinRT (DXGI, Windows.Graphics.Capture, Windows.Media.Ocr), ETW и кодирует изображения. Сервер — это приём данных, базы, очереди, API консоли.

**Решение.** Агент (служба и помощник) — Rust, крейт `windows` от Microsoft. Сервер и воркеры — Go. Контракт — `.proto`-файлы в отдельном репозитории, генерация `tonic` и `grpc-go`.

**Альтернативы.** Всё на Go: проще найм, но DXGI/WGC через ручной COM, WebP через cgo, OCR на агенте недоступен. Всё на Rust: медленнее разработка консольного API. C++: максимальный доступ к API, но небезопасная память в процессе SYSTEM на каждом ПК.

**Последствия.** Два языка в команде и два набора CI. Нужен минимум один сильный Rust-разработчик. Разбор — на странице [Go или Rust](stack.html).

## ADR-002. Агент из двух процессов {#adr-002}

**Статус:** принято.

**Контекст.** Службы Windows работают в изолированной сессии 0 и не видят рабочий стол пользователя.

**Решение.** Служба `RakursAgent` (SYSTEM) отвечает за очередь, сеть, обновления, системную телеметрию и запуск помощника. Помощник `rakurs-session.exe` запускается в каждой интерактивной сессии от имени пользователя и делает снимки, следит за окнами и простоем, показывает трей. Связь — именованный канал с ACL «SYSTEM и владелец сессии».

**Последствия.** Нужно следить за жизнью помощника, обрабатывать быстрое переключение пользователей и RDP. Помощник не имеет сетевого доступа к серверу: всё идёт через службу.

## ADR-003. gRPC поверх HTTP/2 с mTLS {#adr-003}

**Статус:** принято.

**Контекст.** Нужен двунаправленный поток событий, бинарные кадры, взаимная аутентификация агента и сервера, прохождение через корпоративные прокси и балансировщики.

**Решение.** gRPC (HTTP/2, TLS 1.3), клиентский сертификат на каждый агент, выпускаемый внутренним УЦ при регистрации. QUIC — кандидат на вторую версию для филиалов с потерями пакетов.

**Последствия.** Нужен свой мини-УЦ и ротация сертификатов. Балансировщик — L4 с пробросом TLS или L7 с поддержкой gRPC и проверкой клиентских сертификатов.

## ADR-004. Хранение: PostgreSQL + ClickHouse + S3 {#adr-004}

**Статус:** принято.

**Контекст.** Три разных профиля данных: справочники и политики (мало, транзакционно), события (много, только добавление, аналитика), кадры (большие бинарные объекты).

**Решение.** PostgreSQL — ПК, пользователи, политики, роли, журнал аудита. ClickHouse — события и текст OCR, партиции по дням, TTL по сроку хранения. S3-совместимое хранилище — кадры, ключ шифрования на тенант. По умолчанию **SeaweedFS** (Apache-2.0): у MinIO Community в 2025–2026 годах сокращалась функциональность, а затем репозиторий ушёл в архив, поэтому как новую зависимость его не берём. Для крупных инсталляций — Ceph RGW.

**Альтернативы.** TimescaleDB вместо ClickHouse — проще, если команда знает только PostgreSQL, но медленнее на агрегатах по миллиардам строк. Хранить кадры в базе — нет.

**Последствия.** Три системы в эксплуатации; для малых инсталляций (до 200 ПК) допускаем режим «всё в одном»: PostgreSQL + файловое хранилище.

## ADR-005. OCR на сервере {#adr-005}

**Статус:** принято.

**Решение.** Распознавание текста — отдельный воркер на сервере (PaddleOCR через ONNX Runtime, запасной Tesseract). На агенте OCR только как опция для офлайн-филиалов через Windows.Media.Ocr.

**Последствия.** Нагрузка на ПК пользователя не растёт; серверу нужен CPU, при росте — GPU. Модели обновляются централизованно.

## ADR-006. Нет канала удалённых команд {#adr-006}

**Статус:** принято.

**Контекст.** Агенты мониторинга часто умеют выполнять команды, скачивать файлы с ПК, блокировать ввод. Это превращает сервер в единую точку компрометации всего парка.

**Решение.** Сервер может передать агенту только (1) подписанную политику и (2) манифест обновления, подписанный отдельным офлайн-ключом. Других команд нет: ни шелла, ни загрузки файлов, ни снимка «прямо сейчас» по запросу. Live view не делаем в первой версии.

**Последствия.** Расследование опирается на то, что уже собрано по политике. Если ИБ нужна более подробная картина по конкретному ПК, она меняет политику для него, и это изменение видно в журнале аудита и сотруднику.

## ADR-007. Окно сотрудника на Tauri 2, трей нативный {#adr-007}

**Статус:** принято.

**Решение.** Значок в трее — часть помощника (`tray-icon`), без WebView. Окно «Что обо мне собирается» — отдельный процесс на Tauri 2, запускается по клику и завершается при закрытии. Интерфейс собирается из тех же компонентов, что и консоль. Запасной вариант при запрете WebView2 — Slint.

## ADR-008. Нет кейлоггера, скрытого режима и записи звука {#adr-008}

**Статус:** принято, пересмотру не подлежит без решения руководства и юриста.

**Решение.** Агент не перехватывает ввод с клавиатуры, буфер обмена, микрофон и камеру; не скрывается из трея, списка программ и служб; не использует техники обхода антивирусов. Соответствующего кода в агенте нет.

**Последствия.** Часть сценариев DLP закрывается другими средствами (DLP-шлюз, EDR). Агент проще согласовать с антивирусами, юристом и коллективом. См. [Закон и этика](legal.html).

## ADR-009. Очередь задач — NATS JetStream {#adr-009}

**Статус:** предложено.

**Решение.** Между приёмом и воркерами (OCR, правила, миниатюры) — NATS JetStream: один бинарник, персистентность, подтверждения, простая эксплуатация. Kafka избыточна для ожидаемых объёмов.
