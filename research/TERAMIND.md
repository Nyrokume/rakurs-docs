## 1. Как устроен Teramind

### 1.1 Три части

Архитектура клиент–сервер из трёх компонентов ([KB, 26.10.2026](https://knowledge.teramind.co/en/articles/13366708-how-does-teramind-work-architecture)):

1. **Агент** на конечной точке: собирает телеметрию и **сам исполняет** политики и правила, пришедшие с сервера.
2. **Сервер**: принимает поток, считает аналитику, хранит записи, отдаёт веб-консоль.
3. **Dashboard**: отчёты, UBA, проигрыватель сессий, RBAC, редактор политик и правил, настройки агента.

Поток данных с агента (там же):

- сетевой фильтр-драйвер (прокси) разбирает трафик и выделяет события верхнего уровня: письма, страницы, мгновенные сообщения, метаданные;
- файловый фильтр-драйвер следит за операциями с файлами;
- остальные сигналы идут через API ОС (приложения, ввод, экран и т.д.);
- при обрыве связи события копятся локально и досылаются после восстановления;
- на сервер — HTTPS (443), плюс собственный протокол по TLS (в on-prem/private cloud порт 10000) и опционально UDP для звука.

Это ближе к «агент + сервер + консоль», чем к чистому учёту времени. Отличие от «Ясности» в глубине перехвата: у Teramind в архитектуре заложен разбор содержимого сети и файлов, у нас — события и снимки без содержимого писем, трафика и буфера ([telemetry.html](../content/telemetry.md)).

### 1.2 Агент: платформы, режимы, VDI

**Платформы** ([спецификации агента, 10.11.2026](https://knowledge.teramind.co/en/articles/11906389-teramind-agent-specifications-and-supported-platforms)):

- Windows 10 и новее (x64 и ARM64), Windows Server 2016 и новее;
- macOS Monterey 12.7.6 и новее — с ограничениями;
- Linux: Ubuntu 24+, Debian 13+, RHEL 9+, только AMD64 — с ограничениями;
- для старых установок сохраняется ограниченная поддержка Windows 7/8 и Server 2008 R2 / 2012.

Нагрузка по заявлению вендора: примерно 30–50 МБ памяти и 1–3% CPU. Полоса: ориентир 7 КБ/с на экран при слабой активности и 30–60 КБ/с на экран при обычной офисной работе и 2 кадрах в секунду.

**Три типа агента** (на одну машину ставится только один) ([установка, 19.11.2026](https://knowledge.teramind.co/en/articles/17241888-how-to-download-and-install-the-teramind-agent), [архитектура](https://knowledge.teramind.co/en/articles/13366708-how-does-teramind-work-architecture)):

| Тип | Как виден сотруднику | Когда начинает сбор |
|---|---|---|
| **Revealed** (Visible / Freelance) | Видимое приложение. Пользователь сам запускает и останавливает мониторинг, выбирает проект и задачу | Только пока пользователь вошёл в агент и включил задачу. Подходит для подрядчиков и «мягкого» режима |
| **Stealth** (Hidden / Silent) | Работает в фоне, «чтобы пользователь не знал, что его наблюдают» (формулировка KB) | С момента входа в Windows/macOS. Доступен только после проверки (vetting) клиента |
| **Standard** | Как Stealth после установки | На время установки обязателен диалог согласия (Windows и macOS 26.36+). Дальше работает молча, обновления попап больше не показывают. Только для облачных триалов; удалённая установка запрещена, чтобы согласие нельзя было обойти |

«Рабочее время» считается по-разному ([метрики продуктивности, 10.11.2026](https://knowledge.teramind.co/en/articles/11903996-productivity-metrics-faq-how-is-work-time-idle-time-activity-percentage-productive-time-unproductive-time-total-time-determined)): у Stealth это время входа в систему минус блокировка экрана; у Revealed — время, пока в агенте запущена задача.

Офлайн-запись есть у Standard и Stealth (у Revealed — нет, по той же статье спецификаций). По умолчанию выключена, буфер 24 часа, для обычного дня ориентир до 1 ГБ на 8 часов. Правила продолжают действовать и без сети.

**VDI и терминальные сессии:** stand-alone ПК, RDS / terminal server, application/session server, Citrix, VMware Horizon. Агент ставят на хост сессий; вендор советует держаться около 30 пользователей на терминальный сервер, иначе возможна просадка производительности.

Паритет Windows / macOS / Linux неполный ([сравнение ОС, 10.11.2026](https://knowledge.teramind.co/en/articles/15262363-what-features-are-supported-in-windows-mac-and-linux)): на Mac и Linux урезаны почта, мессенджеры, соцсети, часть файловых и сетевых правил, живой удалённый контроль, часть настроек записи экрана. Буфер обмена и консольные команды на macOS не поддерживаются. SSH-сессии (видео + кейстроки) — только Linux.

Развёртывание: тихий MSI, GPO/SCCM, удалённый установщик из консоли (не для Standard). Драйверы подписаны EV-сертификатом; есть отдельный гайд по исключениям антивируса и EDR — это совместимость, не заявленный «обход» защиты. Для Stealth отдельно описана защита установки от удаления.

### 1.3 Облако, on-prem, private cloud

Три модели, по заявлению вендора с полным паритетом функций ([различия моделей, 27.10.2026](https://knowledge.teramind.co/en/articles/12637131-what-is-the-difference-between-teramind-cloud-teramind-on-premises-and-teramind-private-cloud-azure-aws); [архитектура](https://knowledge.teramind.co/en/articles/13366708-how-does-teramind-work-architecture)):

- **Cloud (SaaS):** полностью обслуживает Teramind, хостинг на Oracle Cloud Infrastructure, дата-центры уровня tier-3. В статье о молях указана single-tenant схема (отдельный инстанс и изолированная БД на клиента). Обновления, резервные копии и масштабирование — на стороне вендора.
- **On-premises:** готовый Linux VM-образ под VMware, Hyper-V или Nutanix AHV, в инфраструктуре заказчика. Горизонтальное масштабирование заявлено «от 1 до 200 000+ одновременных сессий»; для крупных установок — несколько узлов, балансировка, HA, E2EE.
- **Private cloud:** тот же образ в аккаунте заказчика на AWS / AWS GovCloud или Azure / Azure Government (GovCloud и Azure Government — в тарифе Enterprise).

OCR в on-prem и private cloud требует отдельных узлов: Mining Node (сам OCR) и Database Node на Elasticsearch; в облаке их поднимает вендор ([OCR](https://kb.teramind.co/en/articles/8791102-how-to-use-the-ocr-optical-character-recognition-features)).

Для российской компании облако на OCI по-прежнему упирается в локализацию ПДн (ч. 5 ст. 18 152-ФЗ) и в оплату/поддержку. Имеет смысл смотреть только on-prem, как уже сказано в [рынке](../content/market.md).

## 2. Подход к анализу действий

Анализ у Teramind складывается из пяти слоёв, которые работают на одних и тех же сигналах агента: **классификация времени**, **правила с действиями**, **накопленный риск и аномалии**, **поиск по экрану (OCR)** и **контентный DLP**. Сверху — дашборды, лента OMNI и выгрузка в SIEM.

### 2.1 Продуктивность: категории, фокус, простой

Это не «одно число продуктивности», а набор мер по источникам данных ([метрики, 10.11.2026](https://knowledge.teramind.co/en/articles/11903996-productivity-metrics-faq-how-is-work-time-idle-time-activity-percentage-productive-time-unproductive-time-total-time-determined); [классификация, 16.10.2026](https://knowledge.teramind.co/en/articles/12720637-how-to-classify-activities-into-productive-unproductive-or-custom-category)):

1. **Считается только активное (сфокусированное) окно.** Время на свёрнутой вкладке не идёт в приложение.
2. Приложения и сайты раскладываются по профилю продуктивности: **Productive / Unproductive / Unclassified**, плюс пользовательские категории. Классификация пишется в момент записи; прошлые данные можно пересчитать («Update Past Classifications») — операция тяжёлая.
3. **Activity Time = Active Time + Idle Time.** Active — только интервалы, где были клавиатура или мышь.
4. **Простой начинается после порога.** По умолчанию 10 минут без ввода; порог задаётся в Monitoring Profile. Перерыв короче порога считается активным временем. Пока экран заблокирован, время не входит в Work Time, только в Session Time.
5. Отдельно считаются Productive Time (с простоем и без), доли в процентах, Unclassified, Work Time (вход или «часы» в Revealed-агенте), **Activity %** (доля интервалов с вводом, нарезка по 5 минутам) и, если включён кейлоггер, число символов, слов и нажатий.
6. В правилах есть условия Time Active / Time Focused / Time Idle — «сколько непрерывно сидел в окне» и «сколько был в фокусе».

Важная оговорка самого вендора: **Activity % нельзя читать в одиночку**. Чтение, совещания и звонки дают низкий балл, хотя человек был занят. Это прямо совпадает с нашей установкой не оценивать «продуктивность одним числом» ([roadmap](../content/roadmap.md)).

Практический вывод для «Ясности»: брать модель «фокус окна + порог простоя + категории приложений/сайтов + табель», не брать счётчики нажатий и единый балл.

### 2.2 Движок правил и политик

Поведенческие правила — ядро и угроз, и «мягкого» надзора за временем ([Rules Guide, 18.09.2026](https://kb.teramind.co/en/articles/8791032-rules-guide); [Behavior](https://kb.teramind.co/en/articles/8808329-behavior); [действия, 08.06.2026](https://knowledge.teramind.co/en/articles/11975039-defining-rule-actions)).

Как это устроено:

- **Политика** — папка похожих правил (например, «PCI» или «этикет»). На политику назначается аудитория (люди, компьютеры, подразделения); правило может аудиторию переопределить.
- **Визуальный редактор** с условиями на естественном языке, регулярными выражениями, общими списками (Shared Lists) и готовыми классами данных. Несколько блоков условий связаны через ИЛИ, внутри блока — обычные критерии.
- Источники условий те же, что у мониторинга: приложения, сайты, почта, файлы, IM, буфер, печать, сеть, расписание, OCR, кейстроки, камера, журналы Windows и т.д.
- Есть сотни шаблонов, в том числе библиотека под MITRE ATT&CK: вендор заявляет **более 350** примеров политик и правил на 13 тактик.
- Набор правил зависит от тарифа: в Starter — ограниченный список (расписание агента, сайты, приложения, IM, плагины, реестр, события журнала Windows). Контентные (Content Sharing) правила — в DLP. OCR-правила — в Enterprise. Аномальные правила — в on-prem.

**Действия при срабатывании** (не все доступны на каждом типе правила и не все есть на Mac/Linux):

| Действие | Что делает | Ограничения |
|---|---|---|
| **Notify** | Письмо адресатам (до 15) | У большинства schedule-правил — почти единственное действие. У OCR по умолчанию не чаще одного оповещения на правило/приложение/пользователя/ПК за 4 минуты |
| **Warn** | Предупреждение на экране сотрудника (есть HTML-шаблон под бренд и ссылку на положение) | — |
| **Block** | Прерывает действие (вкладка закрывается или подменяется заглушкой; черновик письма удаляется; загрузка файла не уходит) | Нет у части контентных правил IM/кейстрок |
| **Lock User** | Блокирует сеанс до разблокировки администратором | **Только Stealth-агент**, на Revealed не исполняется. Обходится через другой локальный аккаунт, recovery или съём диска. На Mac пользователь может войти снова |
| **Redirect** | Перенаправляет на другой URL | Только правила Webpages, только Windows |
| **Record** | Клип «за N минут до и после» нарушения | Имеет смысл, когда непрерывная запись выключена |
| **Switch Task** | Автоматически сменяет задачу (например, на «перерыв») | Только Stealth, только Windows |
| **Command** | Запускает произвольную команду или скрипт Windows (в справке прямые примеры `shutdown` и `taskkill`) | Только Windows; с точки зрения доверия — очень опасный примитив |

В расширенном режиме у одного правила несколько **порогов**: период (час/день/месяц), частота, уровень риска (None / Low / Moderate / High / Critical) и свой набор действий. Пример вендора: 5 загрузок за день — Warn и Low; больше 50 — Block + Notify и High.

Для «Ясности» ближайший уже описанный контур — FR-14: условие, окно времени, порог, действие (консоль, почта, SIEM, вебхук). У Teramind стоит взять идею **эскалации по частоте** и действие **предупредить сотрудника видимым сообщением**. Блокировку, лок сеанса, редирект и произвольные команды — не в продукт мониторинга (у нас блокировка приложений и сайтов уже отнесена к EDR/прокси, [roadmap](../content/roadmap.md)).

### 2.3 Риск-скоринг и UEBA

Здесь два разных механизма, их легко смешать в маркетинге.

**A. Риск по правилам — основной, прозрачный** ([как определяется риск, 15.10.2026](https://knowledge.teramind.co/en/articles/13363314-how-does-teramind-define-risk)):

- у правила есть «Rule violation severity» 0–100 (для Insights) и дискретный уровень в действиях (для Behavior Alerts);
- на дашборде алертов: `Risk Score = Alert Count × Risk Level` (None=0, Low=1, Moderate=2, High=3, …);
- Severity в другой колонке: `Alert Count × Rule Violation Severity`;
- накопление можно включить или выключить (считать повтор или один раз);
- за счёт порогов частоты система отличает разовый срыв от «капельной» привычки и призвана снижать шум.

Это не чёрный ящик, а арифметика над сработавшими правилами. Для открытого мониторинга такой подход честнее: правило и вес можно показать сотруднику в положении.

**B. Anomaly Rules (UEBA-слой)** ([Behavior](https://kb.teramind.co/en/articles/8808329-behavior)):

- доступны в **on-prem** консоли (в статье — «On-Premise/Windows»);
- сравнивают текущее поведение с базовой линией **самого сотрудника, подразделения или организации**;
- действие только **Notify** — систему не блокируют по аномалии;
- задуманы для того, что трудно описать жёстким правилом.

**C. Маркетинговый UEBA / OMNI** ([features](https://www.teramind.co/features/), [OMNI](https://www.teramind.co/solutions/omni/)): «поведенческие базовые линии», «постепенная утечка», «superhuman command velocity», карта связей, «toxicity score» переписки, «worker authenticity» по нюансам набора, Shift и движению мыши. Часть этого — продуктовые обещания ленты OMNI, а не спецификация аномальных правил в KB. Подлинность аккаунта по динамике нажатий по сути поведенческая биометрия; для «Ясности» это отдельный правовой и этический стоп, даже без классического кейлоггера содержимого.

Инсайдерские угрозы в продукте в целом закрываются связкой «правило + запись сессии + риск + (опционально) блок».

### 2.4 OCR и «умный» поиск по записям

([OCR](https://kb.teramind.co/en/articles/8791102-how-to-use-the-ocr-optical-character-recognition-features), [Rules Guide, раздел OCR](https://kb.teramind.co/en/articles/8791032-rules-guide))

- Движок непрерывно снимает и индексирует текст с рабочего стола, в том числе внутри изображений и видео, на нескольких мониторах, в VDI и на терминальных серверах.
- Поиск: `Contains` или regexp в синтаксисе Elasticsearch. В выдаче — снимок с полупрозрачной жёлтой подсветкой найденных областей и переход к записи сессии в тот момент.
- Правила OCR: ключевые слова, regexp, общие списки, порог «сколько раз за день», ограничение приложением, уровень риска. Действие по сути **Notify** (плюс троттлинг). Примеры вендора: полный номер карты на экране, просмотр документа с чувствительными словами, «стеганография» в картинках и видео.
- На on-prem нужны Mining Node + Elasticsearch.

Патент подтверждён независимо: [US 10,853,508 B2](https://patents.google.com/patent/US10853508B2/en) «Method and system for reactive mining of computer screens», правообладатель Teramind Inc., выдана 1 декабря 2020, изобретатели Yizhak Kohen и Andrii Kukareka. Суть — добыча текста с того, что пользователь реально видит на экране, и реакция правилами (журнал, блок, размытие, предупреждение). Для «Ясности» важен принцип (индексация видимого текста + поиск с подсветкой области кадра), а не копирование реализации.

У нас FR-11 и поиск в консоли уже есть; не хватает явного «подсветить область на кадре» и опциональных OCR-оповещений с обоснованием и второй подписью (как у `ocr.region: full` в политике).

### 2.5 DLP

Начиная с тарифа DLP ([pricing](https://www.teramind.co/services/price/), [различия тарифов](https://kb.teramind.co/en/articles/8790885-what-is-the-difference-between-teramind-starter-teramind-uam-teramind-dlp-and-teramind-enterprise)):

- контентные правила, детекция чувствительного содержимого, редактирование (redaction), автоблокировка;
- заявлено «200 готовых DLP-правил», отпечатки и теги данных, шаблоны под GDPR / HIPAA / PCI DSS / CCPA / SOX;
- каналы: USB, облако, почтовые вложения, веб-загрузки, буфер, печать;
- отдельно — контроль вставки в ChatGPT, Claude, Gemini, Copilot (GenAI DLP) и «11 готовых правил» по ИИ (маркетинг на [features](https://www.teramind.co/features/)).

Для «Ясности» v1 DLP такого уровня не цель: у нас события USB и сеть без чтения файлов, размытие окон до записи, правила-оповещения. Контентная блокировка — соседний класс систем. Имеет смысл позже смотреть только на **оповещения** «чувствительный текст попал на экран» (через наш OCR), без перехвата почты и файлов.

### 2.6 Отчёты и BI

- Виджеты с мерами времени (сумма / min / max / avg на запись), готовые дашборды Productivity, Time Worked, Time Cards.
- Behavior Alerts и Insights с разрезом по риску.
- «AI-assisted» конструктор виджетов — заявлено на [features](https://www.teramind.co/features/), устройство модели в KB подробно не разобрано.
- Проигрыватель сессий: живой просмотр, запись, уведомления, которые видел сотрудник, экспорт «для суда» (формулировка вендора).
- Опция не писать экран постоянно, а только вокруг нарушения.

У нас уже заложены отчёты «время в приложениях», табель, загрузка подразделения, инвентаризация, USB, поиск и хронология расследования ([console](../content/console.md)). От Teramind полезны: категории на шкале дня (это у нас уже есть цветом), явное отделение Active/Idle/Unclassified и конструктор мер, а не единый балл.

### 2.7 ИИ-функции: OMNI, мониторинг GenAI

Два разных «ИИ»:

1. **Наблюдение за ИИ-инструментами сотрудников:** обнаружение теневого GenAI (включая локальные LLM — заявлено на features), запись «AI conversations» с тарифа UAM, контентные правила по промптам с тарифа DLP, управление агентными ИИ (в т.ч. OpenClaw, Claude Code) и «скоростью команд». Это практичный слой для ИБ, но содержимое промптов у нас лучше видеть только через OCR снимка и категории приложений, не через кейлоггер.
2. **OMNI** ([страница OMNI](https://www.teramind.co/solutions/omni/)) — лента в духе новостной ленты: карточки похожих событий, снимок, нарушенное правило, карты связей, «toxicity» переписки, дрейф персоны, скоринг инсайдерского риска, модель «подлинности работника» по динамике набора и мыши. Маркетинговые цифры на той же странице («в среднем 7% сотрудников фальсифицировали активность», «токсичность двух команд выросла на 42%») **не подкреплены методом и выборкой**. В отзывах Capterra (2026) OMNI/Insight иногда доступны только администратору и плохо выгружаются.

Для открытого мониторинга лента инцидентов полезна; скоринг «токсичности переписки» и биометрия нажатий — нет.

## 3. Приватность и правовые механизмы

Вендор прямо продаёт и скрытый, и «этичный» режимы. Набор контролей ([employee monitoring](https://www.teramind.co/solutions/employee-monitoring/), [features](https://www.teramind.co/features/), [redaction, 10.01.2026](https://knowledge.teramind.co/en/articles/13358387-does-teramind-support-screenshot-redaction-blackout-blurring-masking-censoring-for-privacy-and-compliance), [ai-info](https://www.teramind.co/ai-info/)):

- выбор Revealed или Stealth;
- расписание мониторинга (только рабочие часы, корпоративная сеть);
- исключение приложений и сайтов;
- **Dynamic Blackout:** исключённое окно автоматически закрашивается в live view и в записи (из коробки);
- **Field-Level Blackout:** маскирование отдельных полей — только как заказная работа professional services;
- заявлено автоматическое скрытие PII, паролей, медицинских сведений (на маркетинговых страницах; в KB подробно описаны именно blackout по приложению/сайту и заказное маскирование полей);
- RBAC: кто смотрит, экспортирует, действует; в маркетинге — «руководитель видит агрегированную аналитику команды»;
- шаблоны согласия и «transparent rollout»;
- кейлоггер и непрерывную запись можно выключить;
- запись только вокруг нарушения правила.

Сертификации — **заявления вендора**, сертификаты в этой заметке из реестров не скачивались ([KB, 26.10.2026](https://knowledge.teramind.co/en/articles/12636586-does-teramind-have-certification-for-gdpr-hipaa-soc-soc2-iso-pci-dss-etc), [ai-info](https://www.teramind.co/ai-info/)):

- ISO/IEC 27001:2022, по словам вендора аккредитация BSI;
- SOC 2 Type II («compliance» / «attestation» — формулировки самого вендора);
- GDPR, HIPAA, PCI DSS, CCPA, SOX — в основном **шаблоны правил и отчётов**, плюс сертификаты **дата-центров OCI**, а не отдельный «сертификат GDPR/HIPAA на продукт»;
- Enterprise: AWS GovCloud / Azure Government;
- заявлены выравнивание на NIST CSF, TLS 1.2+, пентесты не реже чем раз в полгода, скрининг персонала по BS7858:2019.

Сравнение с каноном «Ясности»: у нас нет скрытого режима; размытие делается **на агенте до сохранения** (сильнее, чем закрашивание уже записанного видео); каждый просмотр кадра пишется в неизменяемый журнал, а `privacy.viewNotice` уведомляет сотрудника (`onView` / `daily`); сбор с `person_id` не начинается без подтверждённого ознакомления (FR-09, FR-15). Это уже жёстче типичного RBAC Teramind, где уведомление о каждом просмотре в публичных материалах не описано.

Юридическая рамка для нас (не консультация): скрытый агент и сокрытие от антивируса в российской юрисдикции конфликтуют с идеей гласного мониторинга и с риском по ст. 138.1 УК РФ (специальные технические средства для негласного получения информации) — поэтому в [legal](../content/legal.md) скрытый режим запрещён по принципу. Кейлоггер и перехват переписки дополнительно упираются в соразмерность и в ст. 137–138 УК, а также в минимизацию по 152-ФЗ. Stealth-агент Teramind, Standard-агент «согласие один раз, дальше молча» и действие Lock User, которое работает только в Stealth, в эту рамку не помещаются.

### 4.3 Критика и ограничения

- **Скрытый режим и кейлоггер** задают тон продукта. Даже при наличии Revealed и расписания Stealth — полноценный режим «чтобы не знали». Это бьёт по доверию и плохо стыкуется с «открытым мониторингом». Исследование The Conversation о приложениях мониторинга прямо относит Teramind к инструментам с инвазивными функциями (видео + кейлоггер) и фиксирует тревогу работодателей о доверии ([The Conversation](https://theconversation.com/tracking-apps-monitor-remote-employees-performance-and-invade-their-privacy-256261)).
- **Сложный запуск и кривая обучения** — повторяющийся мотив на G2 и Capterra; OMNI/Insight в одном отзыве Capterra (июль 2026) недоступны команде ИБ и не выгружаются нормальным отчётом.
- **macOS слабее Windows:** в отзыве G2 (2026) — нет записи звука, часть функций «не работает как надо», агент может остановиться из‑за разрешений, его приходится проверять ежедневно. Это согласуется с таблицей паритета в KB.
- **Дороже «дверцы» Starter:** нужные ИБ вещи (кейлоггер, полный UEBA, безлимитные правила) начинаются с UAM; OCR — только Enterprise. WorkTime и Forbes подчёркивают, что глубина слежки избыточна для простого учёта времени ([Forbes Advisor](https://www.forbes.com/advisor/business/software/teramind-review/)).
- Trustpilot в обзоре WorkTime: 2.5 / 5 при **7** отзывах — выборка слишком мала, как самостоятельный вердикт не используем.
- Действие **Command** (произвольный скрипт на ПК сотрудника) и **Lock User только в Stealth** усиливают ощущение средства контроля, а не прозрачного учёта.

## 5. Сравнение с «Ясностью»

Кратко: Teramind — зрелый комбайн «запись + правила + DLP + OCR + UEBA» с скрытым режимом как полноценной опцией. «Ясность» ближе к нему по глубине данных (снимки, процессы, USB, сеть, OCR, расследование), но по этике и правовой рамке — к лагерю открытого учёта. Это уже сформулировано в [рынке](../content/market.md); после разбора Teramind формулировку стоит уточнить (у нас в таблице свойств у Teramind в поле «скрытый режим» ещё стоит «нет данных» — это уже не так).

### 5.1 Таблица: берём / не берём / адаптируем

| Решение Teramind | Вердикт | Как перенести в «Ясность» |
|---|---|---|
| Профили категорий приложений и сайтов; учёт только фокусного окна; порог простоя (у них 10 мин); Active = был ввод, Activity = Active + Idle; без единого балла «продуктивности» | **Берём / адаптируем** | Уже есть цвет категории на шкале дня и отчёт «время в приложениях». Зафиксировать в телеметрии и консоли те же определения, порог простоя в политике, Unclassified как отдельный сегмент. Счётчики нажатий не использовать. Совпадает с «не оценивать одним числом» |
| Редактор правил: пороги частоты, эскалация действий, шаблоны (запрещённое ПО, USB, нерабочее время), предупреждение сотрудника на экране | **Адаптируем** (FR-14) | К уже описанным оповещениям (консоль, почта, SIEM, вебхук) добавить пороги «N раз за период → выше уровень», видимое предупреждение в окне агента и опцию «дописать кадры вокруг срабатывания». | Риск как `число срабатываний × вес правила`, с накоплением «капельных» нарушений | **Адаптируем** (позже, фаза аналитики) | Прозрачный счётчик в консоли ИБ, веса в тексте положения. Не чёрный ящик |
| Anomaly Rules: сравнение с базовой линией человека / подразделения, только Notify | **Адаптируем осторожно, не в v1** | Только после пилота, только оповещение, в положении раскрыто, без блокировок |
| OCR-поиск с подсветкой области на кадре и прыжком к моменту | **Адаптируем** (FR-11, FR-12) | Поиск уже есть; добавить подсветку области и OCR-правила «текст на экране» с `justification` и второй подписью. Индекс — ClickHouse, не обязательно Elasticsearch |
| Dynamic Blackout исключённых окон; расписание «только рабочие часы»; запись только вокруг правила | **Частично уже есть / адаптируем** | Размытие и skip у нас на агенте **до записи** — оставляем как более сильный вариант. Расписание и «кадры вокруг правила» — в политику |
| Stealth / Standard «согласие раз и дальше молча»; кейлоггер; динамика нажатий и мыши (OMNI authenticity); перехват почты, IM, TLS, буфера, файлов; микрофон; камера; геолокация; удалённый захват рабочего стола; произвольная команда на ПК; Lock User | **Не берём** | Канон, ADR-008, legal, telemetry «никогда». Скрытый режим — риск по ст. 138.1 УК; кейлоггер и переписка — ст. 137–138 и несоразмерность; обход/сокрытие от AV — конфликт с EDR. Не юрконсультация |
| Контентный DLP с автоблокировкой, fingerprinting, 200 шаблонами | **Не берём в контур мониторинга** | Оповещение «на экране виден шаблон ПДн/карты» — можно позже через OCR. Блокировка каналов — EDR/DLP/прокси |
| Облако OCI, live view, единый балл продуктивности, «toxicity» переписки | **Не берём / не в v1** | Данные только в контуре заказчика; live view отложен; единый балл запрещён в roadmap; анализ тона переписки — слишком глубоко в коммуникации |

### 5.2 Где «Ясность» может отличаться

- **Гласность как архитектура, а не как пресет:** всегда видимый трей, окно сотрудника с перечнем данных и последними снимками, сбор с `person_id` только после ознакомления, `viewNotice` о каждом просмотре, неизменяемый аудит просмотров. У Teramind гласность — один из режимов, и самый «жёсткий» контроль (Lock User, Switch Task) привязан как раз к Stealth.
- **Минимизация на агенте:** не записать лишнее проще, чем потом закрашивать в плеере. Полевое маскирование у них ещё и платное custom.
- **Правовая рамка РФ** встроена в ТЗ (152-ФЗ, ТК, уведомление Роскомнадзора, выгрузка по ст. 14), а не как набор «GDPR-шаблонов» поверх глобального облака.
- **Стек под контур заказчика:** Rust-агент, Go-сервер, веб-консоль, SeaweedFS + PostgreSQL + ClickHouse, gRPC/mTLS — без проприетарного протокола на порту 10000 и без обязательного Elasticsearch, если хватит нашего индекса OCR.
- **Роли:** специалист ИБ и руководитель только своих подчинённых по AD, проверка на каждом запросе — уже жёстче маркетингового «агрегат по команде».
- Честный отказ от непрерывного видео, live view в v1, кейлоггера и блокировок снижает и юридический, и кадровый риск, ценой меньшей «форензики нажатий».

## 6. Что обновить в документации «Ясности»

Предложения, не правки (эту заметку не коммитим). Нумерацию новых FR не вводить без отдельного решения.

1. **[Рынок](../content/market.md) и [Источники](../content/sources.md).** В таблице свойств у Teramind сейчас «скрытый режим — нет данных»: заменить на подтверждённый Stealth (после vetting) и Standard («согласие на установке, дальше молча»). Уточнить, что OCR — Enterprise, кейлоггер — с UAM, риск по правилам и Anomaly Rules (on-prem, только Notify) существуют. В источники добавить KB по архитектуре, агенту, правилам, метрикам, OCR, риску, redaction и сертификациям. Цены $14 / $28 / $32 оставить с датой и оговоркой, что калькулятор на сайте — JS.
2. **[Консоль](../content/console.md) (FR-12, FR-14) и сводка в [ТЗ](../content/tz.md).** В правилах описать пороги частоты и эскалацию, действие «предупредить сотрудника в окне агента», опцию «дозаписать кадры вокруг срабатывания». В отчётах и ленте дня явно определить Active / Idle / Unclassified и порог простоя; подчеркнуть, что Activity % и аналог «одного балла» не показываем. В поиске — подсветка найденного текста на кадре (как у их OCR search).
3. **[Телеметрия](../content/telemetry.md) и [Политики](../content/policy.md).** Зафиксировать определения времени (только фокусное окно, порог простоя в политике, блокировка экрана не входит в рабочее время). Добавить категорию «ИИ-инструменты» (ChatGPT, Claude, Copilot и т.п.) как приложения/сайты, без перехвата промптов. Расписание сбора «только рабочие часы» уже следует из legal — проверить, что поле политики это закрывает явно.
4. **[Захват и OCR](../content/capture.md) (FR-11) и [Приватность](../content/privacy.md).** Описание поиска: подсветка области, переход к кадру, аудит самого запроса (это уже намечено в консоли). Опциональные OCR-оповещения — только с `justification` и второй подписью, по аналогии с `ocr.region: full`. Сравнить наше размытие «до записи» с их Dynamic Blackout, чтобы не импортировать более слабую модель.
5. **[Дорожная карта](../content/roadmap.md), [Закон и этика](../content/legal.md), при необходимости [Риски](../content/risks.md).** В фазе 3 аналитики: прозрачный риск по правилам, затем (не в v1) аномалии относительно базовой линии с Notify only. Явно перечислить отказ от Stealth-паттерна, кейлоггера, динамики нажатий, live view в v1, автоблокировок и удалённого управления — с отсылкой к этой заметке. В legal можно одним абзацем зафиксировать, что аналоги с скрытым агентом мы разбирали и сознательно не повторяем.

## 7. Что не удалось подтвердить или стоит оговорить

- **Цифры на живом калькуляторе** 26.11.2026 из статического HTML не читаются. Опираемся на блоги вендора от 18.08 и 17.09.2026. Сторонний обзор WorkTime даёт $15 / $30 / $35 — расхождение не закрыто.
- **ISO 27001:2022 и SOC 2 Type II** — только заявления вендора; PDF сертификатов и отчёты аудитора в этой работе не проверялись.
- **«Native» интеграция с Microsoft Sentinel и Asana** есть на features (2026), но отсутствует в KB-списке интеграций от 21.02.2025. Возможно, появилась позже или идёт через Generic CEF/JSON / API. Не подтверждаем как готовый коннектор.
- **Linux OCR:** языки OCR (включая русский) перечислены в спецификациях агента глобально; в Rules Guide OCR описан для Windows и Mac. Однозначной строки «OCR на Linux: supported» в разобранной матрице паритета нет.
- **Автоматическое маскирование PII/паролей/PHI «из коробки»** широко заявлено в маркетинге; в KB подробно описаны Dynamic Blackout (окно целиком) и заказной Field-Level Blackout. Посимвольное авторедактирование в записи как стандартная функция не подтверждено.
- **Маркетинговые цифры OMNI** («7% фальсифицировали активность», «токсичность +42%») без метода, периода и выборки. Не используем как факт.
- **«10 000+ организаций»** на страницах вендора — рекламный показатель, не проверялся.
- **Полнота паритета Cloud / on-prem / private cloud:** так пишет вендор; независимой проверки нет. OCR в on-prem точно требует отдельных узлов.
- **Актуальный статус аномальных правил в облаке:** статья Behavior прямо относит Anomaly Rules к on-prem дашборду. Жив ли тот же функционал в Cloud в ноябре 2026, по публичным страницам однозначно не видно.
- Формулировки вроде «court-admissible / legally admissible evidence» — юридический маркетинг, не оценка допустимости доказательств в РФ.
